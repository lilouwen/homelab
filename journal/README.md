# Lab journal

Document engineering work, not a synthetic contribution history. Add a new Markdown file only for actual work completed or tested.

## Entry template

**Date:** YYYY-MM-DD  
**System:** Example: Docker, WireGuard, DNS  
**Objective:** What should change or what problem is being investigated?

### Baseline

Describe the configuration and symptom observed before the work. Do not publish identifying logs, credentials or personal files.

### Hypothesis and approach

Explain what you expected and why.

### Commands or configuration

Record **sanitized** commands or pseudocode only. Never paste private keys or active secret-bearing files.

### Verification

| Test | Expected | Observed | Result |
|---|---|---|---|
| Example | Service responds from trusted LAN | Not tested | NOT TESTED |

### Lessons learned

Summarize root cause, outcome, rollback steps and next actions. Never claim a test passed without evidence.
